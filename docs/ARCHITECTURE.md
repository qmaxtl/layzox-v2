# Architecture
Vite + React + TypeScript retained. src/main.tsx → src/App.tsx → src/automation. Routes are lazy loaded; the homepage is eager. React Flow is loaded only for /lab. React Hook Form + Zod validate leads; the same schema is imported on the server. Vercel Node function api/leads.ts requires exact allowed origin and durable database configuration. Database RPC atomically rate-limits and stores the enquiry. No browser persistence for personal data. No keys are bundled.
Legacy procurement/Next.js scaffold remains in source for recovery but is outside the active entry graph. TypeScript checks every transitive active import and api/**/*.ts. Legacy authentication and fake-success forms are not reachable. Existing service/enquiry aliases redirect to automation routes; legacy CRM/blog/partner routes are not advertised.
Storage schema is in docs/LEAD_DATABASE.sql. Notification outbox rows start pending. Production requires database provisioning, reviewed service permissions and notification worker configuration. Local Vite preview does not execute Vercel functions; unit tests exercise the server handler with mocked storage.
Build-time prerendering writes complete HTML for all 20 primary routes, with route-specific metadata, canonical URLs and minimal Organization structured data. The client attaches interactivity using the existing React entry point. Vercel serves directory indexes with clean URLs; only legacy aliases rewrite. A static 404 page handles unknown URLs.
Optional notification worker: POST /api/notify-leads with a server-only bearer secret. Disabled unless ENABLE_LEAD_NOTIFICATIONS=true and all provider settings exist. The database atomically claims up to five pending records; retries are eligible after ten minutes. Resend idempotency keys use lead IDs. Email contains a record reference, not the visitor's personal information. Enable scheduling only after owner approval of the recipient and provider. Long-delayed retries beyond the provider's idempotency retention can duplicate an alert; the lead record remains singular.
